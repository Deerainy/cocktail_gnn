# 实体识别与审核系统 - 后端需求文档

## 一、现阶段问题

### 1.1 审核提交失败
- **现象**：点击"提交审核"按钮时，系统显示"提交审核失败，请重试"的错误提示
- **原因**：后端服务未运行或相关API接口未实现
- **影响**：无法完成实体审核流程，系统功能不完整

### 1.2 其他潜在问题
- **任务获取**：`/api/entity/review_tasks` 接口可能未实现，当前前端使用模拟数据
- **任务详情**：`/api/entity/review_tasks/{reviewId}` 接口可能未实现
- **实体处理**：`/api/entity/process` 和 `/api/entity/batch_process` 接口可能未实现

## 二、需要后端提供的内容

### 2.1 API接口实现

#### 2.1.1 实体处理接口
- **Endpoint**: `/api/entity/process`
- **Method**: POST
- **功能**：处理单个文本的实体识别
- **请求体**：
  ```json
  {
    "text": "I want a smoky Margarita with lime juice and mezcal."
  }
  ```
- **响应**：符合前端集成文档中的实体结构

#### 2.1.2 批量处理接口
- **Endpoint**: `/api/entity/batch_process`
- **Method**: POST
- **功能**：批量处理文本的实体识别
- **请求体**：
  ```json
  {
    "texts": [
      "I want a smoky Margarita with lime juice and mezcal.",
      "给我一杯龙舌兰酒加青柠。"
    ]
  }
  ```
- **响应**：实体处理结果数组

#### 2.1.3 审核提交接口
- **Endpoint**: `/api/entity/review`
- **Method**: POST
- **功能**：提交审核结果
- **请求体**：
  ```json
  {
    "review_id": "uuid-123",
    "entity_id": "entity-456",
    "original_text": "Margareta",
    "approved_candidate": {
      "text": "Margarita",
      "label": "RECIPE",
      "entity_id": 723,
      "normalized_name": "Margarita"
    },
    "add_as_alias": true
  }
  ```
- **响应**：
  ```json
  {
    "status": "success",
    "message": "审核结果已处理",
    "data": {
      "review_id": "uuid-123",
      "entity_id": "entity-456",
      "action": "add_alias",
      "alias": "Margareta",
      "canonical_id": 723,
      "canonical_name": "Margarita"
    }
  }
  ```

#### 2.1.4 审核任务列表接口
- **Endpoint**: `/api/entity/review_tasks`
- **Method**: GET
- **功能**：获取审核任务列表
- **响应**：审核任务数组

#### 2.1.5 审核任务详情接口
- **Endpoint**: `/api/entity/review_tasks/{reviewId}`
- **Method**: GET
- **功能**：获取审核任务详情
- **响应**：审核任务详情

### 2.2 数据结构实现

#### 2.2.1 实体结构
- 支持多种实体类型：RECIPE, INGREDIENT, CANONICAL, FLAVOR, ROLE, NOUN
- 包含处理层级：lexicon_rule, fuzzy_match, llm_analysis, unrecognized
- 支持候选实体列表（用于LLM分析）

#### 2.2.2 审核任务结构
- 包含任务ID、时间戳、原始文本、需要审核的实体列表
- 每个实体包含候选实体列表

### 2.3 业务逻辑实现

#### 2.3.1 三层处理逻辑
1. **词典/规则优先**：使用pattern词典、alias映射和标准实体库进行高精度识别
2. **模糊匹配/检索兜底**：处理第一层未命中的实体
3. **LLM候选分析**：对前两层都无法处理的实体，使用LLM进行候选分析

#### 2.3.2 审核处理逻辑
- 接收审核结果
- 根据add_as_alias字段决定是否添加为别名
- 更新实体库和别名映射
- 返回处理结果

### 2.4 服务部署

- 启动后端服务，确保API接口可访问
- 配置正确的CORS设置，允许前端访问
- 确保服务稳定运行
